# containers

Infrastructure-shaped container images, built and published to GHCR.

This repo is for images that support the homelab platform itself — base images, sidecars, CNPG variants, custom inits. **Application images live with their applications**, not here.

## Layout

```
apps/<name>/
  Dockerfile      # the build
  metadata.json   # app name, published version, target platforms
  README.md       # what it is, how to consume
.github/workflows/
  build.yaml      # reusable: build → push → cosign sign → attest → release
  release.yaml    # dispatcher: detects changed apps, fans out via matrix
```

## Tag scheme

Tags are `<upstream_version>-<image_revision>` and are **immutable**. No floating tags (`latest`, `main`, major-only). Always pull by tag **and** digest:

```
ghcr.io/nicolerenee/<app>:<version>@sha256:<digest>
```

The digest is recorded in the per-release GitHub Release notes (`<app>-<version>`).

## How releases happen

1. Open a PR that bumps `apps/<app>/metadata.json` `.version` (and whatever Renovate / human edits triggered the bump in the `Dockerfile`).
2. On merge to `main`, `release.yaml` detects the changed app, calls `build.yaml`.
3. `build.yaml` builds, pushes to GHCR, signs with cosign keyless OIDC, attests SLSA build provenance, then creates the git tag `<app>-<version>` and a GitHub Release with the digest.

Re-running on the same `metadata.json` `.version` is a no-op — the plan step skips apps whose tag already exists. To rebuild, bump the revision suffix.

## Manual builds

`workflow_dispatch` on **Release** with:

- `app` set to a directory under `apps/` — builds just that one (still respects existing-tag check)
- `force_all: true` — replans against every app

## Supply chain

- Cosign keyless signing (Sigstore OIDC, no key material to rotate)
- SLSA build provenance attestation pushed to GHCR alongside the image
- SBOM generated by buildx and embedded in the image index
